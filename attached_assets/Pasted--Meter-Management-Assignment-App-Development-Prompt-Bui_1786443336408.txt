# Meter Management & Assignment App — Development Prompt

Build a production-ready **Meter Management & Tracking Mobile App** using **React Native** for the frontend and **Node.js + Express.js + MongoDB** for the backend.

The app is designed for teams/workers who install electricity/water/utility meters at customer locations and need a centralized system to track:

* Which meter is assigned to which customer/address
* Which meter is currently available
* Which team member has taken a meter
* Who installed/received/assigned the meter
* Customer and meter details
* Installation date
* Meter status
* Cancellation/reason
* Digital signatures
* Customer/location/map information
* Search and filtering
* User authentication and access control

The application should be simple enough for field workers to use quickly from their mobile phones.

# 18. Important Data Ownership Rule

A user should have their own account and list.

Team members should be able to access shared team data only after being added/invited to that team.

Do NOT make all registered users automatically able to see everyone's data.

Implement proper authorization at the backend level.

For example:

```text
User A
 ├── Personal/Team A data
 │
 └── Cannot access Team B data

User B
 ├── Team A data
 │
 └── Team B data
```

The backend must verify ownership/team membership on every protected API.

Never rely only on frontend restrictions.

# 26. Important Business Rules

Implement these rules:

### Rule 1

A meter can belong to only one team at a time.

### Rule 2

A meter cannot be assigned to a user who is not a member of that team.

### Rule 3

A cancelled meter cannot be marked as installed unless an authorized user reopens/reactivates it.

### Rule 4

An installed meter should not be casually reassigned.

Require explicit authorization for changes after installation.

### Rule 5

Every assignment must create a history record.

### Rule 6

Every handover must capture the receiver's signature.

### Rule 7

Cancellation requires a reason.

### Rule 8

Historical records should never be silently deleted/overwritten.

### Rule 9

Users can only access data belonging to teams they are members of.

### Rule 10

AC number and meter serial number should have appropriate uniqueness rules within the relevant team/business context.

# Final Requirement

The final application should feel like a **real production-ready meter inventory + field installation management system**, not a simple CRUD demo.

The primary goal is:

> A team should be able to know at any moment where every meter is, who currently has it, where it needs to be installed, whether it has been installed/cancelled, and have a verifiable digital signature whenever a meter is handed from one team member to another.

Prioritize **data integrity, audit history, team-based access control, fast search, simple field-worker UX, and scalability**.
